# ADR-18 人工修正走**覆写层**：改正文不换 ID，也不重算关联边

- **状态**：Accepted（2026-09-28；用户授权"后边全按推荐"采用，逐题记录见 `specs/001-learning-memory-rag/v08-decisions.md`。LG-005：结论本应由用户撰写，本次由用户明确授权按推荐值采用，可随时改定）
- **日期**：2026-09-28
- **素材**：PRD v0.8.0 FR-028 / FR-030 / NFR-011；spec FR-026 / FR-028
- **实施位置**：`src/entries.py`（生效值解析 + 覆写写入）、`src/ingest.py`（重放不覆盖人工字段）、`src/api/app.py`（`PATCH /entries/{id}`）

## 背景

条目 ID = `uuid5(source|date|content_hash)`，其中 `content_hash` 取自**蒸馏后的正文**（FR-014）。这套规则是幂等与去重的基石（NFR-003）：同一条素材反复入库命中同一个点。

一旦允许人工改正文，就撞上它：**改正文 = 换 ID**。而"换 ID"会连锁出三个问题——旧点删不删、同日重放会不会长回来、`related` 边指向谁。

## 备选与被否的理由

| 方案 | 为何没选 |
|---|---|
| **改正文就换 ID**（复用现有规则，最省事） | 旧点要么删（不可恢复）、要么留（一个素材两个身份）；更糟的是**同日重放会再蒸出同一条素材并生成新 ID**，人工修正等于白做 |
| **换 ID + 墓碑表**（记下旧 content_hash 防止复活） | 墓碑表要新增存储与查询路径，且"哪个 ID 是人工版"需要额外映射；复杂度换来的只是"ID 仍然自洽"这一点美学 |
| **覆写层：ID 不动，另存人工值**（采用） | 幂等规则一行不改；重放天然命中同一个点，只需保证"不覆盖人工字段"这一条合并规则 |

## 证据

- `content_hash` 的定义与量纲见 data-model.md（sha256 十六进制前 16 字符）；它取自正文，故"改正文不换 ID"只能靠**不重算 ID** 实现，没有中间路线。
- 重放是常规操作（AC-009 补跑历史、ADR-14 的重放基线），所以"重放会不会复活/覆盖"不是边角情况，而是**必经路径**。

## 后果与可逆性

- **可逆性**：中等。覆写字段一旦写进 payload，退回"改正文即换 ID"需要对存量做一次性迁移（把覆写值写回 `text` 并重算 ID），属可做但需专门脚本。
- **代价（如实记录）**：库里"显示的正文"不再等于"蒸馏产出的正文"，将来追溯需要同时看两份。缓解：`original_text` **永久保留**、详情页对照展示、检索上下文用当前值并带"已编辑"标记。
- **关联边不重算**（同批决定）：覆写后向量会重算，但 `related` 仍来自**原始蒸馏向量**的相似度。理由：重算会顺着双向边影响别的条目（回填与上限规则），把一次单条编辑变成多条的写操作；而 related 的语义本就是"原始素材层面的相似"。此点记为**已知边界**，在详情页标注。

## 决策

1. 人工编辑**只写覆写字段**：`override`（正文/类型/标签/项目）、`edited_at`、`edited_prev_text`；`original_text` 保存首次的原始蒸馏正文且**永不覆盖**。
2. **ID、`related`、`source_refs`、`date`、`source`、`distill_version` 一律不变**；`date` 与 `source` 在界面上**不可编辑**（它们参与 ID 构造，要改只能走迁移脚本）。
3. 保存时用**生效正文**重算该条向量；Ark 不可用则**拒绝保存**（不做"先存文本后补向量"）。
4. `ingest.upsert` 对已存在点**不覆盖人工字段**；这是本决定的机械落点，由 AC-019 的自动化用例（真跑重放）守住。
5. **不重算 `related`**，作为已知边界写进页面与文档。
