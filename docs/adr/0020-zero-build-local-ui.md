# ADR-20 审阅页**零构建**，且只绑本机（写接口加同源校验）

- **状态**：Accepted（2026-09-28；用户授权按推荐值采用，记录见 `specs/001-learning-memory-rag/v08-decisions.md`）
- **日期**：2026-09-28
- **素材**：PRD v0.8.0 NFR-009 / NFR-010、§3.2 NG-002 撤销；spec FR-024
- **实施位置**：`src/api/app.py`（`GET /` + 写接口的同源校验）、`src/api/ui/`（静态资源）

## 背景

v0.8 要加的第一个"页面"撤销了 NG-002（"Web 前端属未来版本"）。撤销它时同时要决定两件事：**前端怎么造**（引不引第二套工具链）与**它暴露到哪里**（NG-005 不撤销 = 没有鉴权）。

## 备选与被否的理由

| 方案 | 为何没选 |
|---|---|
| **Vite + React/Vue** | 让"备份 = 拷目录、跑起来 = 一个 `.venv`"这条简化失效（多一套 `node_modules` 与构建步骤）。本项目的选型偏好是开源、免费、可逆，且页面只有"列表 + 详情 + 三个写操作" |
| **外部 CDN 拉框架** | 断网即废，而且把第三方脚本引进一个**能写库**的页面 |
| **绑 `0.0.0.0`** | 等于把一个无鉴权的写接口交给整个局域网 |
| **零构建单页 + 只绑 `127.0.0.1` + 写接口同源校验**（采用） | 一个 `.venv` 跑全套；"能写库"这件事的暴露面收在本机 + 本页 |

## 证据

- CI 与门禁都建立在"确定性、可复现"上：多一套 npm 工具链意味着 CI 多一步安装、多一个会漂的 lockfile。
- 无鉴权 + 可写的本机服务有一个真实且常被忽略的风险：浏览器里**任何**页面都能向 `http://localhost:8300` 发跨站写请求（浏览器不会替你拦）。因此仅有"绑本机"不够。

## 后果与可逆性

- **可逆性**：高。页面是静态资源，将来要换框架，接口契约不用动（ADR 只约束"不引外部 CDN、不引构建步骤"）。
- **代价（如实记录）**：交互复杂度上限较低（无组件生态、无响应式框架）。若将来页面长成多视图应用，本 ADR 需要重新评估。

## 决策

1. `GET /` 返回随仓库走的静态单页（HTML + CSS + 原生 JS）；**不引入 npm / 打包步骤 / 外部 CDN**，断网可用。
2. 服务与新增路由只绑 `127.0.0.1`，**不默认监听 `0.0.0.0`**；要开局域网访问必须先撤销 NG-005 并补鉴权。
3. 写接口（`PATCH` / `POST`）校验 `Origin`/`Host` 为本机，并要求自定义请求头（`X-Requested-With`）。
4. 路由层只做校验与调用核心层；核心逻辑在 `src/entries.py`（宪法 II）。
