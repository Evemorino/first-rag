# ADR-14 快照写保护：三条并列拒写 + `ALLOW_SHRINK=1` 明路

- **状态**：**Accepted（2026-09-27 用户裁定）**（LG-005：结论由用户写，AI 只给素材与选项；
  问答清单与逐题答案见 `notes/decision-sheet.md`）
- **日期**：2026-09-26
- **素材**：`specs/001-learning-memory-rag/adr-candidates.md` 的 ADR-c5（AI 整理，2026-09-26）
- **实施位置**：`src/collect.py` 的 `save_snapshot` / `_existing_snapshot`；`src/sync.py` 接线；
  `Makefile` 暴露 `ALLOW_SHRINK=1`

## 背景

`data/raw/<day>.json` 既是快照，也是 `make redistill` 的**重放基线**。原来是裸覆写，
于是"单源验证跑一天"就把当天的**多来源**快照换成了 1 条素材的单来源快照 ——
Qdrant 不受影响（条目是 upsert），受害的只有基线：之后对那天做 diff，比的是
"1 条素材的日"与"库里 27 点"，**不报错，只给一个错的 diff**。

## 备选与被否的理由

| 方案 | 当时为何没选 |
|---|---|
| 裸覆写（原状） | 已**实际造成损失**：09-21/22/24/25/26 五天的快照不可恢复 |
| 一刀切禁止覆盖 | 窄 scope 重跑是合法操作，会被误伤 → 需要留明路 |
| 只比条数（v0.7.4 第一版） | "同数量换来源"拦不住（`{trae:1}` 覆盖 `{claude_code:1}`），v0.7.8 补齐 |
| **写前先备份再覆盖** | 未走 —— 见决策问题 1 |

拒写判据最终是**三条并列**：① 条数变少 ② **有来源从盘上消失** ③ **快照结构读不出来**。

## 证据

- v0.7.4 事故：5 天快照被覆盖，仅 09-18/09-23 有备份可还原，其余**不可恢复**。
- v0.7.8 变异检验：`save_snapshot` + `_existing_snapshot` 的 58 条存活里逻辑类 13 条，
  **13 条全部落在未改动的行上**，新增解析逻辑的逻辑类存活 **0**。
- **代价如实记录**：错误信息的散文带来约 24 条新存活，变异分数 **89.6% → 88.6%**
  （分母 2052 → 2107）；同一轮逻辑覆盖是**上升**的。

## 后果与可逆性

- **可逆性**：改代码 + 门禁 + 一批测试 —— 这是这批决策里**最难回退**的一个。
- 与宪法 V 的写入边界（`WRITE_SITES` 登记 + `only_from` 钉调用方）是同一件事的两面。

## 决策

**用户 2026-09-27 裁定（LG-005：结论由用户写；问答清单见 `notes/decision-sheet.md`）。**

1. **取「拒写 + 人显式开 `ALLOW_SHRINK`」。** 两类失败不对等：挡一次合法操作，代价是多敲一条命令；
   静默弄丢基线，代价是**拿到一个错的结论而不报错** —— 后者更贵，因为它污染的是判断本身
   （diff 看起来完全正常）。「先备份再覆盖」也不是零成本：备份存哪、留多久、谁删，本身又是一处
   会静默出错的地方，而它出错时同样不报错。
2. **代价认，并写明它是什么。** "把错误信息说清楚 → 变异分数下降"（89.6% → 88.6%）记为本条
   **已接受**的代价；同时写明这是**度量口径问题**、不是逻辑缺口 —— 同一轮逻辑类覆盖是上升的，
   新增存活集中在错误信息散文上。想提分，杠杆是把断言收窄到关键词而不是整段文案
   （动手前先验证这 24 条存活是否真来自整段文案断言）。
3. **写明：守卫的完备性由变异测试守、不由覆盖率守。** 依据是本条实测 —— `save_snapshot` +
   `_existing_snapshot` 的 58 条存活里，逻辑类 13 条**全部落在未改动的行上**，新增解析逻辑的
   逻辑类存活为 0。覆盖率看得见"这行跑过"，看不见"写坏的路径没人测"；变异测试看得见。
