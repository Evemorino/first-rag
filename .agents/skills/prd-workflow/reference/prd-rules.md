# PRD 管理规则

创建或更新 PRD 时读取本文件。

## PRD 必备内容

PRD 至少应包含：

- 背景、问题与业务目标；
- 用户角色、用户场景和用户旅程；
- 范围内内容与明确的非目标；
- 功能需求（带唯一 ID，例如 `FR-001`）；
- 非功能需求（带唯一 ID，例如 `NFR-001`）；
- 验收标准或成功指标（带唯一 ID，例如 `AC-001` 或 `SC-001`）；
- 业务规则、边界条件、异常场景和失败处理；
- 依赖、假设、风险与待澄清项；
- 版本、变更记录和决策记录。

## 新需求

1. 创建或补全 PRD；
2. 澄清目标、范围、用户场景、验收标准、边界和非目标；
3. 将未决事项标记为 `[NEEDS CLARIFICATION]`；
4. PRD 满足最低完整度后，才进入 `specify`。

## 增量需求

增量需求不另起一套流程，但应先识别其影响面：

1. 定位受影响的 PRD 章节、FR/NFR/AC、范围和非目标；
2. 更新 PRD，并保留变更原因、版本和兼容性影响；
3. 标识受影响的 spec、plan、tasks、代码、测试和文档；
4. 从最早受影响的阶段重新开始，而不是机械重跑所有阶段；
5. 若变更改变验收、范围、业务规则或对外行为，必须重新进行相关审查与验证。

## 变更控制

下列变更必须先更新 PRD，再更新下游工件：

- 新增、删除或修改功能范围；
- 修改用户角色、核心场景或业务规则；
- 修改验收标准、成功指标或质量目标；
- 修改非目标、兼容性承诺、安全、合规或性能要求；
- 因实施发现而改变原有需求解释。

纯技术实现优化且不影响用户可观察行为、范围或验收标准时，不强制修改 PRD，但必须检查 plan 与 tasks 是否需要更新。
