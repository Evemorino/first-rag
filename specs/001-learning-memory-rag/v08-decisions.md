# v0.8 审阅页与条目修正：质询决策记录

**用途**：`prd-workflow` 阶段四（grill-me）的产物 —— 逐轮记录被问到的决策、用户的回答与理由。
本文件是 `plan.md` 与 `tasks.md` 的输入材料；需求层面的结论（范围、验收）回写 PRD/spec，设计层面的结论在这里定稿后进 plan。

**轮次规则**：每轮只问"前置已定、现在就能答"的问题（frontier），每题带 AI 的推荐答案；用户答完才进下一轮。frontier 清空 = 质询通过。

## Round 1（2026-09-28，用户回答：**全部采用推荐值**）

| # | 问题 | 结论 | 理由 / 边界 |
|---|---|---|---|
| Q1 | 删除的动机是"内容错、冗余"还是"内容敏感、不该留"？ | **本版只服务前者**（软删除 + 可恢复）。**"敏感内容不该留"不在本版解决** | 软删除只是不显示，文本仍在 Qdrant 与 `data/raw/` 快照里；真要抹掉需另立硬删除需求，并一起决定快照里那段素材怎么办（快照是重蒸馏的重放基线） |
| Q2 | 编辑后要不要按改后的措辞能搜到？ | **要在编辑保存时重算该条向量**（用覆写正文嵌入） | 不重算会出现"显示新文字、命中靠旧语义"的不一致。代价：编辑要调一次 Ark；**Ark 不可用时拒绝保存并提示**，不做"先存文本、后补向量" |
| Q3 | 详情页要不要显示"原始蒸馏正文" | **要**，折叠/可展开；覆写值与原始正文并存 | 覆写会让"库里显示的"不再等于"蒸馏产出的"，"当时模型怎么写"本身有学习价值 |
| Q4 | 标签/项目的编辑粒度 | **字段整体覆盖**（保存即整段替换该字段） | 与"一个字段一个覆写值"的语义一致；逐项增删会立刻引出"自动标签与人工标签要不要共存"一类规则 |
| Q5 | 三条易退化的验收怎么验 | **必须自动化**：编辑不换 ID、软删后同日重放不复活、留痕不被重放冲掉（pytest + TestClient，真插库真重放） | 手点一次不会有人在下次改 `ingest` 时再点一次，而这三条恰是改 `ingest` 最容易碰坏的。页面本身只做一次人工冒烟 + 一条"页面可打开且不含外部 URL"的机械断言 |
| Q6 | 只读诊断工具要不要看见软删条目 | **面向人的列表与检索一律排除；只读诊断包含并标注"已删"** | 诊断工具的用途是对账（`make rerun-overlap` / `make batch-edges` / 重蒸馏 diff），也过滤会让"页面 90 条、工具说 95 条"变成新谜题 |

**未采纳的候选及原因**：硬删除（Q1，缺动机且牵动重放基线）、编辑后自动保留"文本与向量两套并存"（Q2，两套语义需要额外规则，收益不抵成本）。

## Round 2（2026-09-28，用户回答：**全部采用推荐值**）

| # | 问题 | 结论 | 理由 / 边界 |
|---|---|---|---|
| Q1 | 软删条目怎么找回来 | 列表过滤加**"显示已删除"开关（默认关）**；打开后灰显 + 删除时间 + 恢复按钮 | 没有入口的"可恢复"只是理论上的 |
| Q2 | 编辑后关联边要不要重算 | **不重算**，详情页标注"关联边基于原始蒸馏正文" | 重算会顺着双向边牵动别人的边（回填与上限规则），把单条编辑变成可能影响多条的写操作；related 的语义本就是"原始素材层面的相似" |
| Q3 | 人工编辑能造出配置外类型吗 | **不能**：类型为配置内下拉；标签自由输入，保存前 trim + 去重 + 保序；项目自由文本 | 否则库里会出现 schema 不认的类型，而采集侧仍在按 FR-012 丢弃同类值，两边不一致 |
| Q4 | 编辑历史保留几版 | **原始蒸馏正文永久保留、不可覆盖**；人工编辑只留"最近一次变更前正文"；**不做版本链、不做独立撤销按钮** | 本版目标是校正，不是版本管理 |
| Q5 | 页面形态与入口 | **`GET /` 即审阅页**（打开 `localhost:8300` 就是），JSON API 原地不动；详情为同页右侧面板 + `#/entry/<id>` 锚点 | 零依赖、可刷新、可回退，不引路由库 |
| Q6 | 删除原因必填吗 | **可选** | 强制填的结果通常是人为了删掉而现编理由，反而污染记录 |
| Q7 | 页面要不要带"问一句"入口 | **本版不做**；问答继续走 CLI 与 `/ask` | 那属新增范围，要加就先改 PRD 加 FR，不偷偷塞进实现 |

## Round 3（2026-09-28，用户授权"**后边全按推荐**"：不再逐轮问，剩余分支按下列推荐值采用）

这些是设计树剩下的叶子。列出来是为了**不留下"默默假设"**——其中标〔plan〕的属实现选择，会在 `plan.md` 里再次露面，你可在那时推翻。

| # | 分支 | 采用值 | 理由 |
|---|---|---|---|
| R1 | 软删是"物理摘向量"还是"检索期过滤" | **检索期按 payload 过滤**（`deleted_at` 不存在即可见），不物理删向量 | 保住可恢复性与 ID 不变；代价是查询必须带该条件，几百到几千点的量级可忽略 |
| R2 | 无鉴权本机服务的写接口要不要防跨站 | **要**：写接口校验 `Origin`/`Host` 为本机，并要求一个自定义请求头 | 浏览器里的其他页面能向 `localhost:8300` 发跨站请求；没有这一步，"不出本机"只挡了别人，没挡住你自己的浏览器 |
| R3 | 两个标签页同时编辑同一条 | **乐观并发**：保存时带上读到的版本，版本不符则拒绝并提示刷新 | 单用户也可能开两个页面；比"后写覆盖先写"少一个静默丢改动的路径 |
| R4 | 编辑会不会碰 `date`/`source`/`source_refs`/`distill_version`/`related` | **都不碰**，只写覆写字段与留痕字段 | 前两者参与 ID 构造，后两者是"原始蒸馏事实"，人工润色不改事实 |
| R5 | 列表分页 〔plan〕 | 默认每页 50 条，按需加载下一页 | 够用且不引入前端分页库 |
| R6 | 核心逻辑与页面的放置 〔plan〕 | 核心逻辑放 `src/`（可单测、进变异范围）；页面静态资源与路由薄壳分开放；**若新增 `src/` 目录，按宪法登记进 `scripts/lint_layers.py` 的 `DIRECTORIES`** | 宪法硬约束：新目录必须登记，兜底是拒绝 |
| R7 | 测试怎么造数据 | 复用既有的**内嵌 Qdrant fixture**（`:memory:`）；Round 1 Q5 定的三条验收写成真跑重放的集成用例 | 与 `tests/integration/` 现有做法一致，不引第二套夹具 |
